# Security

Brainmerge runs only on your Mac. This page says what it touches, what it never does, how those promises are enforced, and how to report a problem.

## What it touches

| Where | What Brainmerge does there |
| --- | --- |
| `~/Library/Application Support/Brainmerge` | Its own state (the list of accounts and memories, its settings, such as the menu bar icon), icons, usage cache. No secrets. |
| `~/Applications/Brainmerge/<Name>.app` | One small launcher app per account (ad hoc signed), or a local tinted copy of Claude when you ask for a distinct Dock icon. For your first account, which is Claude itself, only when you switch on its own app: the same small app with its color or photo, which asks macOS to open Claude and does nothing else. The Usage screen adds up its size (for a tinted copy, only the blocks it does not share with Claude). |
| `~/.claude-<slug>` and `~/.claude` | Claude Code profiles. Brainmerge adds one hook (`brainmerge sync`) to `settings.json`, one marked block to `CLAUDE.md`, and links `projects/<slug>/memory` into the memory. Everything else in them is yours and untouched. The Usage screen adds up their size the same way as for Claude's data folder; a shared history or shared skills (links to your first account's) are counted once, with your first account. |
| `.claude.json` (`~/.claude.json` for `~/.claude`, inside the folder for the others) | Claude Code's own file, read and never written. Brainmerge keeps two things from it: the paths of your projects (the keys of `projects`), and the three display fields Claude Code records for the account it last used (`oauthAccount`: email, display name, organization name). Never the rest of that entry, its identifiers, plan or limits, never any other value of the file. The login itself stays in the keychain, untouched. The email is shown in the window to tell accounts apart, and never stored, logged, written to a memory, printed by the command line or sent anywhere. |
| Claude Code, when you click "Check limits" | On the Usage screen, and only on that click, Brainmerge runs that account's official Claude Code: `claude --version`, then `claude -p "/usage"`, the same as typing /usage. It looks for Claude Code at absolute paths, never through `PATH`: `~/.local/bin/claude` (what runs is the version that link points to), then `/opt/homebrew/bin/claude`, then `/usr/local/bin/claude`. The first one found must be signed with Anthropic's Developer ID (team `Q6L2SF6YDW`, identifier `com.anthropic.claude-code`), checked with the Security framework, and be version 2.1.275 or later; otherwise nothing runs and the card says why. It gets no input and three variables only: `HOME`, a minimal `PATH` (`/usr/bin:/bin:/usr/sbin:/sbin`) and, for an account other than the default `~/.claude`, its `CLAUDE_CONFIG_DIR`. Nothing of Brainmerge's own environment reaches it. It is stopped after 20 seconds. Claude Code answers with its own login and asks Anthropic, exactly as when you type /usage; Brainmerge never sees that login. Brainmerge reads only the lines it prints (each limit's percentage and reset time), keeps them in memory until it quits, and never writes them anywhere. Never on a timer, never in a capture or a demo. |
| `~/Applications` and `/Applications` (top level only) | Read, never run or changed. To find apps you made yourself for an account (for instance a copy of Claude whose executable is a launch script), Brainmerge reads each app's `Info.plist` (under 1 MB) and the first two bytes of its executable; only when they are `#!` and the file is under 64 KB, the rest of that script, for the two folders it passes to Claude (`--user-data-dir=` and `CLAUDE_CONFIG_DIR=`). No link inside an app is followed, so nothing outside it is read, and nothing inside those folders either; Brainmerge's own apps and Claude itself are skipped, and `/Applications` is read only for your real home folder. The edit sheet and `brainmerge doctor` say which account such an app opens; Brainmerge never opens, adopts, re-signs, moves or trashes it: you retire it yourself. |
| `~/Library/Application Support/Claude-<slug>` and `~/Library/Application Support/Claude` | Claude's own data folder for each account (the second one is your first account's), created empty; Claude fills it when you log in. Brainmerge only checks whether Claude's storage files exist there, never what is inside. The Usage screen adds up the disk space the folder takes from file metadata while listing it (sizes and names, never contents): no file in it is opened, no name is kept, links are not followed and no other disk is entered. A folder in a place macOS guards with a consent prompt (Desktop, Documents, Downloads, iCloud Drive, cloud storage, other disks) is never walked and shows "Not measured". |
| Running processes | `ps` lists every process with its number, its parent, its resident size and its arguments, never its environment (an environment can hold API keys). Brainmerge keeps the arguments only of command lines that mention "claude" (in any case), to recognize each account and Claude Code; for every other process it keeps the number, the parent and the resident size, and drops the arguments as soon as they are read. For each account's Claude, each Claude Code session in a terminal and the programs they start, it asks the kernel for one number, the RAM each uses (`proc_pid_rusage`, the figure Activity Monitor shows). It never reads another process's memory, environment or open files, which is also why a Claude Code session in a terminal cannot be tied to an account. The Mac's own RAM figures come from the kernel's statistics, with no subprocess. |
| Your memories (`~/Brain` by default) | Markdown notes and a git repository. The hook commits under the account's name. |
| Obsidian vaults you pick for the graph | Read only, on your Mac, never written. The Memory screen's graph can show an Obsidian vault the way Obsidian shows it: Brainmerge reads the paths of your vaults from Obsidian's own list (`~/Library/Application Support/obsidian/obsidian.json`, nothing else from it), the vault's file names and dates, the text of the notes its graph shows (to find their links; notes its filters hide are not opened), and two settings files, `.obsidian/graph.json` and `.obsidian/app.json`. A vault in a place macOS guards with a consent prompt (Documents, Desktop, Downloads, iCloud Drive, cloud storage, another disk) is listed as Obsidian lists it, without a look at its folder, and read only once you pick it: macOS may then ask you once to let Brainmerge read that folder. If you say no, the graph says so and reads nothing. It never creates, changes or moves a file in the vault, never runs git there, and never turns it into a memory. A click opens the note in Obsidian through its `obsidian://` link. |
| `~/.local/bin/brainmerge` | A symbolic link to the command line inside the app. |

## What it never does

- **No network.** No call to Anthropic, to us, or to anyone: no server, no telemetry, no crash reports, no update check that connects. "Check for updates" opens the releases page in your browser, and "Star on GitHub" (menu bar, Settings, the guide's last step) opens the project's page there too; Brainmerge itself fetches nothing from either. The menu bar icon shows what the window already knows: nothing more is read for it. "Check limits" starts that account's own Claude Code, which asks Anthropic exactly as when you type /usage; Brainmerge itself connects to nothing.
- **No credentials.** It never reads, stores or transmits a password, a session cookie, a token or a keychain item. "Connected" is decided from the names of files in Claude's data folder, never from their contents. Folder sizes come from file metadata, never from file contents. The email a card shows is the one Claude Code records for display, read as described above. Limits are never read by Brainmerge itself: they are the text Claude Code prints when you click "Check limits", never a file, a login or the keychain.
- **No account tricks.** No rotation, no switching when a limit is reached, no pooled usage, no automation of the login. Each account logs in by itself, in the official Claude app.
- **No modified Claude by default.** Accounts start the installed Claude through a launcher that only sets two folders. The optional distinct icon copies Claude on your own Mac, after checking that its signature is intact, and is never distributed. Your first account is never copied: its optional own app only opens Claude, which is why the Dock still shows Claude's icon while it runs.
- **No shell.** Programs (git, codesign, cp, iconutil, open, and Claude Code for "Check limits") are started with argument lists, never through a shell, so an account name can never become a command.

## How the promises are enforced

- `SecurityGuardTests` scan the whole source tree at every test run: no networking API, no shell interpreter, a single place that starts processes, Claude's storage files named only in one file that may not read contents, no analytics library. Claude Code's account entry is read in one file only, by typed decoding of its three display fields (its decodable keys are checked to be exactly those, with no identifiers, tokens, plan, roles or limits, no path taken from the process), and no shipped file names an API key, a token cache, the keychain entry or usage fields. The file that looks for apps you made only reads: no process, no opening, no writing, no moving, no trash, a short list of file calls, and every file opened read only without following a link. The file that adds up disk sizes walks without following links or entering another disk, and opens, reads, writes or starts nothing; the file that plans which folders to walk only reads the text of links, and never lists a folder or reads a file. The files that list Obsidian vaults, read their graph settings and build their graph only read: no writing, no process, no git, no memory created, and Obsidian's list decoded for its paths alone. No shipped file reads another process's arguments through the kernel (which would bring its environment), its memory or its open files; only the process monitor asks for a process's RAM, and its single `ps` call is pinned to arguments that never print an environment. The files that find Claude Code and ask it for limits open no file, decode no JSON, look at no login or keychain, take nothing from Brainmerge's own environment, and ask exactly `--version` and `-p "/usage"`. Other tests check that Claude Code gets only the variables Brainmerge gives it (never an API key or a token Brainmerge's own environment may hold), that only the button asks, never a clock, and that no file holds a limit afterwards.
- `NameRules` keep every name to one line without control characters, so names are safe in file names, plists, git authors and Claude's instructions.
- The launcher refuses any configuration that would start something other than a Claude binary inside an app bundle, or use relative folders.
- The first account's own app opens one app only: the Claude pinned in its Info.plist when it was built, at an absolute path, whose Info.plist says it is Claude and whose code is signed by Anthropic's Developer ID (team `Q6L2SF6YDW`), checked with the Security framework, never a subprocess. A hand-made or tinted copy of Claude carries Claude's bundle identifier but not Anthropic's signature, and is refused. It passes no folder and no environment, so Claude opens on its own folders, exactly as from Finder.
- "Check limits" runs Claude Code only once the Security framework confirms Anthropic's Developer ID (team `Q6L2SF6YDW`) and Claude Code's identifier on the file that runs: the file a link points to, never the link, so the link cannot be swapped between the check and the run. An unsigned copy, or one signed by anyone else, is refused with a sentence, and nothing else is tried in its place.
- Dependencies are pinned in `Package.resolved` and watched by Dependabot; CI runs with read-only permissions.
- The app is built with the hardened runtime. Releases are signed with a Developer ID and notarized by Apple, and the disk image carries Apple's ticket.

## What to keep in mind

- What you put in a memory, Claude reads at the start of every session, in every account attached to it. Share a memory folder only with people you trust, and never write secrets in it.
- A memory of its own for a work or client account keeps what it learns apart from the shared memory.
- Removing Brainmerge (Settings, or `brainmerge uninstall`) undoes all of the above and deletes none of your data.

## Reporting a vulnerability

If you find a way in which Brainmerge could leak data, run something it should not, or break one of the rules above, please report it privately rather than in a public issue: use "Report a vulnerability" on the Security tab of the repository. You will get an answer within a week, and a fix before any public disclosure.
