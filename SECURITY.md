# Security

Brainmerge runs only on your Mac. This page says what it touches, what it never does, how those promises are enforced, and how to report a problem.

## What it touches

| Where | What Brainmerge does there |
| --- | --- |
| `~/Library/Application Support/Brainmerge` | Its own state (the list of accounts and memories, its settings, such as the menu bar icon and the Claude app you chose), icons, usage cache. No secrets. Each save first keeps the previous state as `state.previous.json`, and the app and the command line change the state one at a time, under a lock on `state.lock`. A state that cannot be read is never replaced: Brainmerge says so on its own screen and offers to restore the previous copy when this version can read it, keeping the unreadable file beside it. |
| `~/Applications/Brainmerge/<Name>.app` | One small launcher app per account (ad hoc signed), or a local tinted copy of Claude when you ask for a distinct Dock icon. For your first account, which is Claude itself, only when you switch on its own app: the same small app with its color or photo, which asks macOS to open Claude and does nothing else. The Usage screen adds up its size (for a tinted copy, only the blocks it does not share with Claude). |
| `~/.claude-<slug>` and `~/.claude` | Claude Code profiles. Brainmerge adds three hooks to `settings.json`, `brainmerge sync` when Claude finishes (it saves what this account wrote in the memory), `brainmerge wire` when a session starts (it links that project's memory) and `brainmerge touched` after an edit tool (Write, Edit, MultiEdit) wrote a file (it notes the file when it is one of a memory's notes), one marked block to `CLAUDE.md`, and links `projects/<slug>/memory` into the memory. Each hook runs only if Brainmerge's command line is still there and always ends with success, so a Brainmerge moved or trashed never blocks a session; one written by an older Brainmerge is replaced where it stands, and your own hooks are never touched. Of what Claude Code sends a hook when a session starts, `wire` decodes only the folder the session runs in (`cwd`), never the session's id, its transcript or anything else; of what it sends after an edit, `touched` decodes only the file's path (`tool_input.file_path`), never the text written, the tool's answer or the session. Both print nothing; and writes a line to `~/Library/Logs/Brainmerge/sync.log` when it links a project, as `sync` does for each save. Everything else in them is yours and untouched. The Usage screen adds up their size the same way as for Claude's data folder; a shared history or shared skills (links to your first account's) are counted once, with your first account. |
| `.claude.json` (`~/.claude.json` for `~/.claude`, inside the folder for the others) | Claude Code's own file, read and never written. Brainmerge keeps two things from it: the paths of your projects (the keys of `projects`), and the three display fields Claude Code records for the account it last used (`oauthAccount`: email, display name, organization name). Never the rest of that entry, its identifiers, plan or limits, never any other value of the file. For the edit sheet's Connections, it also reads the names of the MCP servers there (the keys of the top-level `mcpServers` and of each project's `mcpServers`), never their values, which can hold commands, keys or headers. The login itself stays in the keychain, untouched. The email is shown in the window to tell accounts apart, and never stored, logged, written to a memory, printed by the command line or sent anywhere. |
| Claude Code, when you click "Check limits" | On the Usage screen, and only on that click, Brainmerge runs that account's official Claude Code: `claude --version`, then `claude -p "/usage"`, the same as typing /usage. It looks for Claude Code at absolute paths, never through `PATH`: `~/.local/bin/claude` (what runs is the version that link points to), then `/opt/homebrew/bin/claude`, then `/usr/local/bin/claude`. The first one found must be signed with Anthropic's Developer ID (team `Q6L2SF6YDW`, identifier `com.anthropic.claude-code`), checked with the Security framework, and be version 2.1.275 or later; otherwise nothing runs and the card says why. It gets no input and three variables only: `HOME`, a minimal `PATH` (`/usr/bin:/bin:/usr/sbin:/sbin`) and, for an account other than the default `~/.claude`, its `CLAUDE_CONFIG_DIR`. Nothing of Brainmerge's own environment reaches it. It is stopped after 20 seconds. Claude Code answers with its own login and asks Anthropic, exactly as when you type /usage; Brainmerge never sees that login. Brainmerge reads only the lines it prints (each limit's percentage and reset time), keeps them in memory until it quits, and never writes them anywhere itself. Claude Code handles the run like any session it starts: it runs in your home folder with the settings and hooks it loads there (for an account other than the default, that can include `~/.claude/settings.json`, which it reads as that folder's project settings), and it may keep its own record of the session, what /usage printed included, in that account's files, as when you type /usage. If an account's card changes to another login (removed, added again under the same name, or moved to another Claude Code folder), what was found for the old one is dropped. Never on a timer, never in a capture or a demo. |
| `~/Applications` and `/Applications` (top level only) | Read, never run or changed. To find apps you made yourself for an account (for instance a copy of Claude whose executable is a launch script), Brainmerge reads each app's `Info.plist` (under 1 MB) and the first two bytes of its executable; only when they are `#!` and the file is under 64 KB, the rest of that script, for the two folders it passes to Claude (`--user-data-dir=` and `CLAUDE_CONFIG_DIR=`). No link inside an app is followed, so nothing outside it is read, and nothing inside those folders either; Brainmerge's own apps and Claude itself are skipped, and `/Applications` is read only for your real home folder. The edit sheet and `brainmerge doctor` say which account such an app opens; Brainmerge never opens, adopts, re-signs, moves or trashes it: you retire it yourself. |
| `~/Library/Application Support/Claude-<slug>` and `~/Library/Application Support/Claude` | Claude's own data folder for each account (the second one is your first account's), created empty; Claude fills it when you log in. Brainmerge only checks whether Claude's storage files exist there, never what is inside. The Usage screen adds up the disk space the folder takes from file metadata while listing it (sizes and names, never contents): no file in it is opened, no name is kept, links are not followed and no other disk is entered. A folder in a place macOS guards with a consent prompt (Desktop, Documents, Downloads, iCloud Drive, cloud storage, other disks) is never walked and shows "Not measured". |
| Running processes | `ps` lists every process with its number, its parent, its resident size and its arguments, never its environment (an environment can hold API keys). Brainmerge keeps the arguments only of command lines that mention "claude" (in any case), to recognize each account and Claude Code; for every other process it keeps the number, the parent and the resident size, and drops the arguments as soon as they are read. For each account's Claude, each Claude Code session in a terminal and the programs they start, it asks the kernel for one number, the RAM each uses (`proc_pid_rusage`, the figure Activity Monitor shows), and for each account's Claude window when it started, from the same kernel call, to tell a window older than a Claude update. It never reads another process's memory, environment or open files, which is also why a Claude Code session in a terminal cannot be tied to an account. The Mac's own RAM figures come from the kernel's statistics, with no subprocess. |
| Your memories (`~/Brain` by default) | Markdown notes and a git repository. Each account's PostToolUse hook lists the notes it writes in `.brainmerge/touched/<account>` (Brainmerge adds that folder to the memory's `.gitignore`, appending only), and its Stop hook commits exactly those, under the account's name: another account's notes waiting for their own save, and your own files, are never in its commit. The SessionStart hook adds the project it links to the memory's list of projects, and that account's next save commits the list. Your own edits (outside Claude) are committed by the app as You, never by a hook, and only from the memory's own files (`memory/`, `BRAIN.md`, `.gitignore`, and the lists of projects and accounts in `.brainmerge/`), once nothing changed for ten minutes and no Claude Code session runs; Settings, Memories, can turn that off. Anything else in the folder, such as an Obsidian vault's settings or daily notes, is never committed. Before each save commits, the secret guard reads the lines that save adds to the notes (`git diff --cached -U0`: never the rest of a note, never a line saved before) and holds back a note with a line shaped like a key (a private key's header, an Anthropic, OpenAI, GitHub, GitLab, Slack, AWS, Google, Stripe live or npm key, or a key, secret, password or token set to a long random value): that note is left out of the commit, and the rest is saved exactly as the guard read it: each save stages in an index of its own, so a note rewritten meanwhile waits for the next save, and when the guard cannot tell which note a line came from, nothing is saved. Of a held note Brainmerge keeps its path, the line's number, the shape and the line's SHA-256 in `~/Library/Application Support/Brainmerge/held/<memory>.json`, never the line or the value, which is never shown, logged or copied either. "It's not a secret" adds that SHA-256 to `.brainmerge/not-secrets.json` in the memory (saved with your own edits, digests only); "Save anyway" lets that note through once. While your own git is stopped half way in a memory (a merge, a rebase or a cherry-pick not finished, or conflicts left in the index), no save commits there until you finish: a save never completes your merge or keeps conflict markers. When another git (an editor's, a plugin's) holds the memory's index as a save ends, the save is made anyway, and the names of the files it saved wait in `.git/brainmerge-index-behind` until git's index catches up, at the next save or within a minute. A memory folder inside another git repository is refused when you choose it. Known limit: when two accounts edit the same `MEMORY.md` before either saves, the first save commits both edits under its name. |
| Obsidian vaults you pick for the graph | Read only, on your Mac, never written. The Memory screen's graph can show an Obsidian vault the way Obsidian shows it: Brainmerge reads the paths of your vaults from Obsidian's own list (`~/Library/Application Support/obsidian/obsidian.json`, nothing else from it), the vault's file names and dates, the text of the notes its graph shows (to find their links; notes its filters hide are not opened), and two settings files, `.obsidian/graph.json` and `.obsidian/app.json`. A vault in a place macOS guards with a consent prompt (Documents, Desktop, Downloads, iCloud Drive, cloud storage, another disk) is listed as Obsidian lists it, without a look at its folder, and read only once you pick it: macOS may then ask you once to let Brainmerge read that folder. If you say no, the graph says so and reads nothing. It never creates, changes or moves a file in the vault, never runs git there, and never turns it into a memory. A click opens the note in Obsidian through its `obsidian://` link. |
| `claude_desktop_config.json` and `Claude Extensions` in each account's Claude data folder | Read, never written, for the edit sheet's Connections: the names of the Claude app's MCP servers (the keys of `mcpServers`, never their values) and the folder names of its Desktop Extensions. Nothing else of the file, such as the browser pairing, is decoded. Nothing is copied between accounts. |
| Chrome, Arc, Brave and Edge's `Local State` | Read, never written, only when you open an account's edit sheet: the id of each browser profile and the name the browser shows for it. The Google address and ids the browser keeps next to that name are never decoded. The profile you pick for an account is saved on that account when you save the sheet. "Open <Browser> (<Profile>)" asks macOS to start that browser, found by absolute path and checked by its bundle identifier, with `--profile-directory` set to the profile's id; "Manage connectors" opens `https://claude.ai/customize/connectors` in that profile, or in your default browser when none is picked. A picked profile that is gone is said as such, never replaced by another profile or the default browser, which may be logged into another account. Brainmerge may now open your browser this way, on your click only; the browser, not Brainmerge, connects to claude.ai. |
| Apple's Command Line Tools (`xcode-select`) | The one Apple program Brainmerge starts for setup: `/usr/bin/xcode-select -p` to see whether git is installed (it never shows a dialog). It runs once per run of the app, and once per run of the command line when that run needs git: the Stop hook that saves the memory at the end of each Claude Code session, `brainmerge doctor`, and the commands that create a memory or read its history. The app asks again each time the guided setup opens, when you click "Check again", and every 5 seconds only while the setup or the Memory screen waits for git. Then `/usr/bin/xcode-select --install` only when you click "Install Apple's tools", which opens Apple's own installer. The download comes from Apple, not from Brainmerge. Until git is there, Brainmerge never starts `/usr/bin/git`, so macOS never pops its install dialog on its own. |
| Where Claude is installed | Read only. Brainmerge looks for the Claude app in `/Applications`, then `~/Applications`, then wherever macOS knows it by its bundle identifier, and keeps only a copy signed by Anthropic (team `Q6L2SF6YDW`, checked with the Security framework), never its own apps or a copy made by hand. A Claude you pick in Settings, Where Claude is, is refused unless Anthropic signed it. |
| `~/.local/bin/brainmerge` | A symbolic link to the command line inside the app, which every hook calls. Once the guided setup has made it, each launch makes it again if it is missing, and points it at the app that runs when the Brainmerge it pointed at was moved or trashed. A link that works, or that Brainmerge did not make, and a file of yours are left as they are; a copy running from the disk image links nothing. |

## What it never does

- **No network.** No call to Anthropic, to us, or to anyone: no server, no telemetry, no crash reports, no update check that connects. "Check for updates" opens the releases page in your browser, and "Star on GitHub" (menu bar, Settings, the guide's last step) opens the project's page there too; Brainmerge itself fetches nothing from either. The menu bar icon shows what the window already knows: nothing more is read for it. "Check limits" starts that account's own Claude Code, which asks Anthropic exactly as when you type /usage; the Connections buttons open your browser, which loads the page. Brainmerge itself connects to nothing.
- **No credentials.** It never reads, stores or transmits a password, a session cookie, a token or a keychain item. "Connected" is decided from the names of files in Claude's data folder, never from their contents. Folder sizes come from file metadata, never from file contents. The email a card shows is the one Claude Code records for display, read as described above. Limits are never read by Brainmerge itself: they are the text Claude Code prints when you click "Check limits", never a file, a login or the keychain. The one place a key could pass before its eyes is a note: the secret guard reads the lines a save adds to your notes only to hold back one that looks like a key, and keeps nothing of the line (see Your memories above).
- **No account tricks.** No rotation, no switching when a limit is reached, no pooled usage, no automation of the login. Each account logs in by itself, in the official Claude app. "Log in" only closes your other Claude windows (the same clean quit as Quit), opens the account, and reopens the others when you click; you log in yourself, and Brainmerge never touches your browser, the login link, the keychain or the keyboard. After a Claude update, a window is restarted only when you click Restart or Restart When Idle.
- **No modified Claude by default.** Accounts start the installed Claude through a launcher that only sets two folders. The optional distinct icon copies Claude on your own Mac, after checking that its signature is intact, and is never distributed. Your first account is never copied: its optional own app only opens Claude, which is why the Dock still shows Claude's icon while it runs.
- **No shell.** Programs (git, xcode-select, codesign, cp, iconutil, open, which also starts your browser for Connections, and Claude Code for "Check limits") are started with argument lists, never through a shell, so an account name can never become a command.

## How the promises are enforced

- `SecurityGuardTests` scan the whole source tree at every test run: no networking API, no shell interpreter, a single place that starts processes, Claude's storage files named only in one file that may not read contents, no analytics library. Claude Code's account entry is read in one file only, by typed decoding of its three display fields (its decodable keys are checked to be exactly those, with no identifiers, tokens, plan, roles or limits, no path taken from the process), and no shipped file names an API key, a token cache, the keychain entry or usage fields. The file that looks for apps you made only reads: no process, no opening, no writing, no moving, no trash, a short list of file calls, and every file opened read only without following a link. The file that adds up disk sizes walks without following links or entering another disk, and opens, reads, writes or starts nothing; the file that plans which folders to walk only reads the text of links, and never lists a folder or reads a file. The files that list Obsidian vaults, read their graph settings and build their graph only read: no writing, no process, no git, no memory created, and Obsidian's list decoded for its paths alone. No shipped file reads another process's arguments through the kernel (which would bring its environment), its memory or its open files; only the process monitor asks for a process's RAM, and its single `ps` call is pinned to arguments that never print an environment. The two files that read Connections decode names only, each checked key by key: a browser profile's id and display name (never the Google address or ids next to it), and MCP server names (never their values, which can hold keys); no other file names a browser's profile list or Claude's MCP settings, and the only files and page they can name are listed in the test. The SessionStart hook's input is decoded by one type whose only key is checked to be the session's folder (`cwd`), the PostToolUse hook's by one whose only keys are checked to be the edit's file path (`tool_input.file_path`), and only the wire and touched commands read their input. No shipped file adds and commits a whole memory: a save adds exactly its own paths. The secret guard's findings are checked to hold no text of the line (a path, a number, a shape and a digest), and its tests build their key-shaped values when they run, so the repository holds none. The files that find Claude Code and ask it for limits open no file, decode no JSON, look at no login or keychain, take nothing from Brainmerge's own environment, and ask exactly `--version` and `-p "/usage"`. `xcode-select` is started in one file, only with `-p` or `--install`. Other tests check that Claude Code gets only the variables Brainmerge gives it (never an API key or a token Brainmerge's own environment may hold), that only the button asks, never a clock, and that no file holds a limit afterwards.
- `NameRules` keep every name to one line without control characters, so names are safe in file names, plists, git authors and Claude's instructions.
- The launcher refuses any configuration that would start something other than a Claude binary inside an app bundle, or use relative folders.
- The first account's own app opens one app only: the Claude pinned in its Info.plist when it was built, at an absolute path, whose Info.plist says it is Claude and whose code is signed by Anthropic's Developer ID (team `Q6L2SF6YDW`), checked with the Security framework, never a subprocess. A hand-made or tinted copy of Claude carries Claude's bundle identifier but not Anthropic's signature, and is refused. It passes no folder and no environment, so Claude opens on its own folders, exactly as from Finder.
- "Check limits" runs Claude Code only once the Security framework confirms Anthropic's Developer ID (team `Q6L2SF6YDW`) and Claude Code's identifier on the file that runs: the file a link points to, never the link, so the link cannot be swapped between the check and the run. An unsigned copy, or one signed by anyone else, is refused with a sentence, and nothing else is tried in its place.
- Dependencies are pinned in `Package.resolved` and watched by Dependabot; CI runs with read-only permissions.
- The app is built with the hardened runtime. Releases are signed with a Developer ID and notarized by Apple, and the disk image carries Apple's ticket.

## What to keep in mind

- What you put in a memory, Claude reads at the start of every session, in every account attached to it. Share a memory folder only with people you trust, and never write secrets in it.
- A memory of its own for a work or client account keeps what it learns apart from the shared memory.
- Removing Brainmerge (Settings, or `brainmerge uninstall`) undoes all of the above and deletes none of your data.

## Reporting a vulnerability

If you find a way in which Brainmerge could leak data, run something it should not, or break one of the rules above, please report it privately rather than in a public issue: use "Report a vulnerability" on the Security tab of the repository. You will get an answer within a week, and a fix before any public disclosure.
